# Multi-User Mode — Disabled

Multi-user and remote MCP operation are currently disabled pending a separately
reviewed authentication and authorization profile. The server rejects
`--multi-user`, `LOGOS_MCP_REMOTE_MODE=true`, and non-loopback listener binds.
Do not use the historical instructions below or expose MCP listeners to a
network. The local server requires `LOGOS_MCP_LOCAL_TOKEN` and authenticates
HTTP, WebSocket, and REPL connections.

The previous multi-user notes are retained below as historical context only;
they are not executable guidance.

> [!WARNING]
> Multi-user mode is under development and not yet fully integrated.
> This information is provided for testing purposes only.

The Logos MCP server supports a multi-user mode, allowing multiple Logos users
to connect to the same MCP server instance simultaneously.
This supports remote deployments of the MCP server, without requiring each user
to run their own server instance.

## Limitations

Multi-user mode has the limitation that tools which read from or write to
the local file system are not supported, as the server cannot access
the client's file system. This affects the import and export tools.

## Running Components in Multi-User Mode

To run the MCP server and the Logos MCP plugin in multi-user mode (for testing),
you can use the following command:

```shell
npm run bootstrap:multi-user
```

This will:
* launch the MCP server in multi-user mode (adding the `--multi-user` flag),
* build and launch the Logos MCP plugin server in multi-user mode.

See the package.json scripts for both `mcp-server` and `logos-plugin` for details.

In multi-user mode, users are required to be authenticated via a token.

* This token is provided in the URL used to connect to the MCP server,
  e.g. `http://localhost:4401/mcp?userToken=USER_TOKEN`.
* The same token must be provided when connecting the Logos MCP plugin
  to the MCP server.    
  In the future, the token will, most likely be generated by Logos and
  provided to the plugin automatically.
  :warning: For now, it is hard-coded in the plugin's source code for testing purposes.
