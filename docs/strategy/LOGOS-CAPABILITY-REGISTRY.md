# Logos Capability Registry — P0 Baseline

**Baseline:** `964676b90398f4458a72e3d41fd87e0dc91f51f9` (`main`, 2026-11-10)
**Scope:** Source, build, test, and historical-source inventory; no product behavior is certified by file presence alone.

## Status vocabulary

- **Implemented** — relevant source or contract exists.
- **Verified** — a named automated or browser check exercises the stated behavior.
- **Blocked** — an integration, ownership, artifact, or test gap prevents a product claim.
- **Proposed** — an unimplemented direction or acceptance test.

“Penpot heritage” below means a documented/source-history relationship, not an assertion of binary compatibility or present-day product parity. The historical source snapshot at `665bb1ef13c3eeff2e84bf6e0d588a6bdecc6a92` contains `frontend/`, `common/`, `render-wasm/`, `plugins/`, and `mcp/`; the current root no longer contains `frontend/` or `common/`. The Rust and TypeScript files include port/compatibility comments naming the old `common/src/app/common/...` paths. The exact upstream Penpot commit ancestry and a capability-by-capability semantic diff have not been independently established. See [Working Editor Integration Gaps](../architecture/WORKING-EDITOR-INTEGRATION-GAPS.md) and the historical compatibility assessment in `docs/r1/PKG-00-F03-LEGACY-WORKSPACE-COMPATIBILITY-DECISION.md`.

## Evidence limits and decision

- The current editor route is a compatibility composition, not a verified React editor: React dashboard/auth routes hand off to the legacy `/workspace.html` shell. The current build does not produce its expected `dist/js/main.js` bundle.
- Source counts, documentation, historical Penpot screenshots, and Rust unit tests are not user-journey evidence.
- Main’s renderer workflow verifies WASM packaging and browser pixels for a standalone test scene. Run #236 passed; it does not cover login, project/file permissions, real document loading, editing, save, reload, offline recovery, or collaboration.
- The root README’s 60fps, collaboration, DTCG-runtime, and “zero-loss migration” product claims are not established by this baseline. No 60fps, 10,000-shape, zero-loss import, or no-data-loss claim is verified.

**P0 decision:** inventory is established; product baseline is not accepted. Keep dependent feature expansion gated until the editor entrypoint, canonical document/storage contracts, persistence, and renderer ownership have named owners and executable acceptance evidence. See [P0 implementation backlog](P0-IMPLEMENTATION-BACKLOG.md).
