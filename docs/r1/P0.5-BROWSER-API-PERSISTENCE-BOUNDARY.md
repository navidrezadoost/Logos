# P0.5 Track C — Browser-to-API Persistence Boundary

**Scope:** test-only extension of the P0.4 versioned adapter and disposable-DB proof. No production persistence service, route, schema, or document format is added or changed.

## Executable boundaries

Run the existing proof orchestration against a fresh, disposable PostgreSQL database on loopback. The DB name must begin with `logos_p04` because the inherited script enforces that guard:

```sh
TEST_DATABASE_URL=postgres://…@127.0.0.1:5432/logos_p04_boundary?sslmode=disable \
  bash test/p0.4/document-contract/run-disposable-db-proof.sh
```

The adapter tests still produce the existing `legacy-filedata-to-react/v1` projection and Go `mod-obj` wire shape. The Go HTTP test starts the production `server.New` router on an ephemeral loopback listener and sends requests through its existing `/api/rpc/command/{create-file,get-file,update-file}` routes. It exercises the real session middleware using a valid test JWE cookie and disposable `http_session_v2` row created with `auth.CreateSession`.

The HTTP test checks anonymous `get-file` is rejected (401), a separately authenticated non-member cannot update (403), incompatible `vern` and future `revn` requests return their typed 422 conflicts without advancing state, the adapter operation saves and reloads structurally, and a second adapter-generated request based at revision 0 is accepted as stale against revision 1. It verifies the stale response reports server revision 1, the persisted/reloaded revision reaches 2, two `file_change` rows exist with a rebased row, and the final geometry, identity/order, fill, and unknown-field sentinel survive reload.

For the actual browser proof, build and run the isolated harness against the same kind of disposable database:

```sh
(cd logos-app && npm ci --ignore-scripts --no-audit --no-fund)
TEST_DATABASE_URL=postgres://…@127.0.0.1:5432/logos_p04_boundary?sslmode=disable \
P05_BROWSER_BIN="$(command -v google-chrome-stable)" \
  bash test/p0.5/browser-persistence/run-browser-api-proof.sh
```

`TestP05BrowserToAPIPersistence` starts a test-only wrapper around the production Go router. A test-only endpoint sets an HttpOnly/SameSite cookie containing a valid JWE/session; headless Chrome then follows the redirect to the isolated harness. In the browser, the existing API client fetches `get-file`, the versioned adapter validates/projects the rectangle, `documentStore.updateShape` performs the geometry edit, the adapter emits the existing Go `mod-obj` operation, browser `fetch` posts `update-file`, and `get-file` reloads the result. The browser assertion checks revision 1, document/page/root order, shape UUID, edited geometry, solid fill, and the unknown-extension sentinel. The browser DOM evidence is emitted in the Go test log.

## Local verification and limits

- `npm ci --ignore-scripts --no-audit --no-fund` and `./node_modules/.bin/tsc --noEmit` passed; the isolated Vite harness built successfully.
- On a fresh, loopback-only PostgreSQL container using image digest `postgres@sha256:16bc17c64a573ef34162af9298258d1aec548232985b33ed7b1eac33ba35c229`, the P0.4 HTTP/save/rebase proof and P0.5 Chrome browser proof both passed. The container had no host volume and was stopped/removed on exit. Schema setup applied the 149 SQL migrations registered by legacy commit `665bb1ef13c3eeff2e84bf6e0d588a6bdecc6a92`, the empty-database schema effect of legacy Clojure migration 0023, the no-profile-row effect of Clojure migration 0145, and Go migration `0001_project_description_photo.sql`.
- These are local disposable-schema results. A dedicated [P0.5 workflow](../../.github/workflows/p05-browser-persistence.yml) now provisions the same pinned, disposable schema and runs the browser/API proof; its hosted result is pending. The generic Go workflow still skips DB tests without `TEST_DATABASE_URL`.

The browser test uses a valid test-minted session cookie; it does not exercise the login UI, registration, production `WorkspacePage` hydration/save wiring, or real editor routing. The isolated harness calls the existing Zustand command but does not render Canvas or verify visual output (Track B owns rendering). It is not evidence of full-document Penpot fidelity, production schema certification, or feature parity. The test schema and adapter remain provisional and synthetic.
