# G1-B9.2 — Workspace Identity Isolation

## Status and scope

This change isolates asynchronous workspace opening attempts over the existing shared Zustand document store. It does not change the server document format, grant Rust mutation authority, or migrate legacy IDs. A route attempt owns one monotonically increasing generation, even when navigation returns to the same document (`A → B → A`).

## Source-backed lifecycle inventory

| Boundary | Current behavior | Ownership rule |
| --- | --- | --- |
| Route entry/exit | `WorkspacePage` creates a session for project, file, and page route parameters; cleanup disposes only that session | Only the active generation may reset or expose editor UI |
| Workspace reset | `resetWorkspaceDocument` clears selection and atomically installs a fresh empty page/shape graph | Guard is checked before the store update |
| IndexedDB read | `readPersistedDocument` returns a record without mutating Zustand | Apply occurs separately and only for the still-current session |
| Hydration | `hydrateWorkspaceDocument` validates the complete document and sets page graph, identity, and identity source in one update | Guard is checked at the actual mutation boundary |
| Page selection | `setCurrentPage` checks the supplied owner predicate before mutation | A stale URL page cannot affect the newer document |
| Server identity | The route ID is not proof of ownership; cached identity association requires exact returned file ID and ordered page membership | The owner predicate and existing identity contract must both pass |
| Persistence | `buildSnapshot(state)` captures a synchronous immutable projection at subscription notification; debounce writes use that captured projection | Timer and status effects are owner-scoped; teardown cancels pending timers and handles are instance-scoped |
| Snapshot writes | Per-document queue serializes writes to the same key | An older delayed write cannot finish after a newer write for that same key |
| Sync | Each awaited read, fetch, send, delete, status, and conflict application is followed or guarded by an ownership check | A superseded manager cannot send/delete a pending op or apply server conflict state |
| Offline identity issuance | Concurrent `createOfflineDocument` calls share one promise and candidate UUID; identity is promoted only after the initial snapshot writer resolves | Failed writes leave identity unbound; retry reuses the candidate; an optional session guard rejects promotion if ownership changes during the write |
| Legacy identity | Snapshots without the newer identity metadata remain classified as legacy | Historical page and document IDs are not regenerated |

## Invariant

For any workspace attempt `S`, every asynchronous continuation must verify `S.isCurrent()` after each await, and every shared-store mutation or external side effect must check the same predicate immediately before it occurs. A stale attempt may finish its isolated read, but it cannot change the active document graph, identity, selected page, persistence owner, sync owner, or renderer scene.

`WorkspacePage` withholds Canvas and editor panels until the active route has completed its open sequence. This prevents a render of the previous workspace in the interval between router parameter change and the new effect completing its reset.

## Regression evidence

`logos-app/test/workspace-identity-isolation.test.ts` uses deferred promises and fake IndexedDB. Its 13 cases cover delayed stale hydration, delayed `getFile`, unmount, rejected server ID/page ownership, `A → B → A`, immutable initial persistence capture, post-teardown debounce, stale sync fetch, stale sync acknowledgement, concurrent creation, failed creation/retry, stale creation ownership, and legacy nanoid reload.

`logos-app/src/test-support/g1-b9-2-workspace-isolation.tsx` mounts the production `WorkspacePage` and Canvas under a router. The Chromium runner seeds two isolated cached documents, holds A's server identity response, navigates to B, checks the active store and Canvas page/frame, then releases A and verifies the B document, page, shape graph, and renderer page remain active with no browser errors.

## Compatibility and limits

- The shared Zustand store remains the existing document store; this adds no parallel registry of document contents. The session coordinator only records which route attempt currently owns mutations.
- IndexedDB transaction completion is the production persistence boundary already used by this client. Fake IndexedDB verifies ordering and object capture, but does not establish browser storage durability, quota behavior, eviction policy, or crash recovery on physical devices.
- The sync adapter in this application is a stub. Tests prove local lifecycle guards around its async interface; they do not certify a production WebSocket protocol or server authorization behavior.
- The current workspace loading contract restores cached snapshots. It does not add a general uncached Go-to-React document hydration adapter.
- In-flight writes that were validly started while their owner was current may finish after navigation. Their snapshot and document key were captured at start, and same-key ordering is serialized; ownership prevents scheduling later writes or publishing stale status.
- A current `getFile` failure leaves a usable cached workspace available offline. It does not establish canonical server identity beyond whatever was previously verified in the persisted snapshot.
