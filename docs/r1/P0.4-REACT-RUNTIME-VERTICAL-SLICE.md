# P0.4 Track B — React/Rust Renderer Slice

**Baseline:** `1b516cdd087e6c281ba5b9fc125cea57bfaeb5b0`
**Scope:** isolated Vite test page using the existing React `Canvas`, stores, `scene.ts` serializer, committed P0 fixture, and current Rust/Emscripten renderer. No production route, editor model, renderer algorithm, or runtime mapping was changed.

## Test-only vertical slice

`logos-app/test-harness/p04-react-renderer-smoke.html` mounts the existing `Canvas` component. `p04-renderer-fixture.ts` maps only the committed nil-root rectangle to the existing React page/shape types; it preserves UUID, root order, bounds, solid fill and an unknown-extension sidecar, and rejects other shape discriminants.

The browser smoke is built by a separate Vite config into `build-renderer-smoke`, not into the product bundle. It preloads the real Emscripten module, uses the real canvas serializer and renderer, checks the Skia/WebGL mode, samples the fixture color and transparent background, selects the rectangle with the existing scale tool, performs one scale drag, and samples the updated geometry.

One explicit **test-only hierarchy adapter** creates the renderer's nil-UUID root and attaches the fixture's ordered root IDs with the existing `_set_children_1` ABI, then calls the renderer's original full-scene `_render_sync`. Production `scene.ts` does not create/attach this nil-root child list. The adapter makes the missing boundary visible; it is not a production fix or evidence that the unadapted product Canvas works end to end.

## Root scene lifecycle investigation

The production path is currently:

1. The test fixture projection populates `Page.rootShapeIds` and the React `shapes` record. In the app, `useCurrentPageShapes()` resolves that ordered root-ID list to shape objects.
2. A shape edit goes through `documentStore.updateShape`, which replaces the edited object and the `shapes` record. The selector emits a new shallow-compared array; `Canvas`'s effect depends on `shapes`, `size`, `zoom`, and pan, so it calls `syncScene` on the update. The resize interaction therefore triggers React-side synchronization; it is not a missing Zustand dirty notification in this slice.
3. `syncScene` resizes the renderer viewbox, calls `_init_shapes_pool`, uploads each top-level `Shape` via `_set_shape_base_props`, uploads only the first solid fill via `applySolidFill`, then calls `_render_sync`. For geometry, `bounds {x,y,w,h}` is encoded as `selrect {x1:x,y1:y,x2:x+w,y2:y+h}` alongside the transform and rotation. Rust selects the shape and calls `touch_current()` before applying those fields. `_init_shapes_pool` resets the pool counter and UUID lookup, but reuses backing `Shape` slots; it does not itself clear all per-shape properties. Although pool capacity counts immediate `children`, the uploader does not recursively submit children and does not call any `set_children*` ABI.
4. `parentId: null` is serialized as the nil UUID. Rust's base-properties setter selects the shape and sets its `parent_id`; it does not materialize the nil root or add the shape to the parent's ordered `children`. Rust's `set_parent_for_current_shape` explicitly assumes a separate children-list update. The existing `set_children*` exports support that part of the ABI, but this React serializer does not call them.
5. Production `_render_sync` first rebuilds tiles, then renders the whole scene. Whole-scene traversal in `render_shape_tree_partial` looks up the nil UUID and returns `Root shape not found` when it is absent. Rust's `render_sync_shape(id...)` alternative also creates the nil-root object if needed, but only sets the selected shape's parent and renders that shape directly. The harness instead supplies a test-only root/children list and calls full-scene `_render_sync`; it does not establish multi-child order, nested-scene behavior, or production hierarchy wiring.

The first production blocker is scene construction (root object, ordered child links, and recursive descendants), not a missing React notification or generic “dirty flag” omission. A second rendering blocker is now experimentally visible: with the test-only root/children adapter in place, the real full-scene `_render_sync` path is invoked, the 104-byte geometry payload changes, but the framebuffer retains the old pixels. This narrows the remaining failure to Rust state/tile invalidation or presentation after upload; its exact internal cause is not yet proven. The pool reuses shape slots and the serializer does not establish a complete reset contract for properties it omits, so stale slot fields are an additional lifecycle risk. Unknown shape types currently map to raw type `3` (rectangle) in `scene.ts`; this is a separate fail-closed compatibility defect and must be fixed before production integration is accepted. These findings do not authorize renderer-algorithm or persisted-document changes.

The presentation/readback path is also explicit in the smoke: `initCanvasContext` obtains WebGL2, registers/makes the Emscripten GL context current, and calls Rust `_init`; the Rust GPU state captures the currently bound framebuffer and wraps the render target with bottom-left origin. The harness records that target before `_init`, calls `gl.finish()`, binds the target, checks framebuffer completeness, flips logical Y for `readPixels`, and fails on WebGL errors. It records initial interior/background RGBA and post-edit old/new-region RGBA. This verifies the test target, not a separate DOM screenshot or a production route.

| Boundary | Current behavior | Evidence / limitation |
| --- | --- | --- |
| Nil-root creation | No production root creation in `syncScene`; test bridge creates one nil-root frame | `render_sync` requires nil root; bridge is isolated test support |
| Page root IDs → renderer children | Root IDs feed the React selector, but production has no ordered `set_children*` calls | Test bridge submits one child; multi-child order/hierarchy is not proven |
| Descendant upload | Pool capacity counts immediate child lengths, but upload loop is top-level only | Nested shapes are not proven and currently are not recursively uploaded |
| Geometry invalidation | Zustand replacement triggers Canvas effect; serializer marks the shape touched and submits updated selrect | Host evidence: ABI bounds changed, but old/new sampled pixels stayed at the initial color after full-scene `_render_sync` |
| Presentation/readback | Skia target wraps the bound WebGL framebuffer; harness reads it directly and checks errors | Readback is valid/complete with no WebGL errors, but visible post-edit invalidation still fails |

The Rust workflow runs fixture adapter unit tests, builds the isolated harness, and runs it in headless Chrome with SwiftShader. It preserves the DOM result and Chrome/preview logs as a CI artifact. The latest final-head run passed initial color/background pixels and React geometry update, but timed out waiting for the renderer pixel change. The added ABI diagnostic confirms the uploaded selrect bytes changed, while framebuffer samples remained stale. Browser acceptance remains blocked.

## Remaining blockers and decision requested

- `scene.ts` still defaults unknown shape kinds to the rectangle discriminant; production behavior was not changed here.
- The root bridge shows a missing React-to-renderer hierarchy step. A separately reviewable production adapter/runtime change needs Graphics and Frontend ownership and must follow the approved runtime ADR.
- This slice does not call the Go backend or persist/reload; Track C supplies separate disposable DB evidence.
- The latest hosted React Canvas smoke still fails post-edit pixels. React bounds change to `{x:17.7509690068,y:23.8754845034,w:64.4980619864,h:32.2490309932}`, and the 104-byte ABI carries selrects `[10,20,90,60]` then `[17.7509689331,23.8754844666,82.2490310669,56.1245155334]`; nevertheless, both old/new framebuffer samples remain `[51,102,153,255]`. No redraw loop or assertion weakening was added.

**Decision requested:** review the isolated smoke and its root bridge as feasibility evidence only. Decide whether to authorize a separate production adapter PR after the hosted pixels/interaction check, and keep the runtime strategy/route unchanged pending ADR approval.
