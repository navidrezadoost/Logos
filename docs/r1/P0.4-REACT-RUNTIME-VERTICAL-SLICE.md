# P0.4 Track B — React/Rust Renderer Slice

**Baseline:** `1b516cdd087e6c281ba5b9fc125cea57bfaeb5b0`
**Scope:** isolated Vite test page using the existing React `Canvas`, stores, `scene.ts` serializer, committed P0 fixture, and current Rust/Emscripten renderer. No production route, editor model, renderer algorithm, or runtime mapping was changed.

## Test-only vertical slice

`logos-app/test-harness/p04-react-renderer-smoke.html` mounts the existing `Canvas` component. `p04-renderer-fixture.ts` maps only the committed nil-root rectangle to the existing React page/shape types; it preserves UUID, root order, bounds, solid fill and an unknown-extension sidecar, and rejects other shape discriminants.

The browser smoke is built by a separate Vite config into `build-renderer-smoke`, not into the product bundle. It preloads the real Emscripten module, uses the real canvas serializer and renderer, checks the Skia/WebGL mode, samples the fixture color and transparent background, selects the rectangle with the existing scale tool, performs one scale drag, and samples the updated geometry.

One explicit **test-only nil-root bridge** wraps the renderer pool/render calls to create the nil UUID root and attach the ordered page-root child. Current `scene.ts` initializes a pool and serializes shapes but does not itself initialize/attach the root child list required by Rust `render_sync`. This bridge makes the test boundary visible; it is not a production fix or evidence that the unadapted product Canvas works end to end.

The Rust workflow now runs fixture adapter unit tests, builds the isolated harness, and runs it in headless Chrome with SwiftShader. It preserves the DOM result and Chrome/preview logs as a CI artifact. Browser acceptance is pending that hosted run.
