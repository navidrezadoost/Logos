## Executed contract

1. Node tests for `legacy-filedata-to-react/v1`, including stable document/page/shape UUIDs, nil-root-to-`Page.rootShapeIds` mapping, sibling order, geometry, solid fill, and the unknown-field sentinel.
2. Test-only adapter output: a `mod-obj` operation using the existing Go wire shape (`id`, `page-id`, `operations` with `attr`/`val`). It changes only the rectangle x-coordinate from 10 to 15; it does not serialize React-only state as authoritative data.
3. `TestP04FixturePersistenceSaveReloadIntegration`: creates a file through `CreateFileHandler`, seeds the committed synthetic source vector into that disposable file, loads it through `GetFileHandler`/`filedata.NormalizeFileData`, rejects anonymous reads and a non-member update, applies the generated operation through `UpdateFileHandler`, then reloads through `GetFileHandler`.
4. A Node verification of the reloaded Go response against the same test-only projection. The test asserts unchanged document/page/shape UUIDs, nil-root ordering, solid fill, the `extension-p0` sentinel, geometry x=15, `file.revn=1`, and one `file_change` row.

Unsupported shape kinds produce `P04AdapterError(UNSUPPORTED_SHAPE)` in the test adapter. No unsupported shape is mapped to a rectangle by this adapter. This does not change the production `scene.ts` fallback; that remains a separate renderer contract issue.

## Fidelity boundary and remaining blockers

- The adapter is synthetic-fixture-specific and explicitly versioned. It is not imported into the product bundle and must not become a persistence format.
- The server-side save/reload and authorization boundaries are exercised together, but the browser editor path, `WorkspacePage` hydration, Rust rendering, and a full production document remain unverified.
- The current React store does not have a general unknown-field bag; the test-only sidecar is only a sentinel/loss probe. Do not promote it as a production preservation design without contract-owner approval.
- Historical schema lineage and deployed-version comparison remain provisional.

**Decision requested:** accept this as a synthetic, disposable-schema persistence proof only. Keep the historical schema provisional and require the named domain/backend/frontend owners to approve a production adapter contract before promoting any conversion or save behavior.
