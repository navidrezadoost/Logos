# P0.5 Track E — Runtime Security and Revision Contracts

**Base:** `f309baa72fbcd66c81f9215e91d4e4e05461f846`
**Scope:** Go WebSocket Origin/resource authorization and fail-closed stale-revision history handling. No route, schema, cookie format, persisted document, or renderer change is made.

## Implemented contracts

### WebSocket Origin and resource access

- `wsCheckOrigin` rejects missing, malformed, or opaque origins, cross-host/cross-port origins, and scheme mismatches. Same-origin requests are accepted; TLS-terminating proxy deployments must configure exact browser origins in `BACKEND_GO_WEBSOCKET_ALLOWED_ORIGINS`, parsed into `server.Deps.WebSocketAllowedOrigins`. It never trusts `X-Forwarded-Proto`; direct TLS uses `r.TLS`. Unit and real router WebSocket-upgrade tests cover absent, rejected, same-origin, and allowlisted origins. Missing `Origin` is deliberately rejected by default; non-browser clients must send an allowed Origin too.
- The WebSocket handler receives the existing database pool. `subscribe-file` and `subscribe-team` require `CanRead` from the existing file/team permission queries. Query errors, missing pools, and absent memberships deny access.
- `pointer-update` requires file read access. Resource notifications are reauthorized when enqueued and again immediately before the WebSocket write. Active subscription state, a per-channel generation, and retained resource classification make unsubscribe/resubscribe races fail closed; the final eligibility check/enqueue and socket write serialize with unsubscribe. A denied event is dropped, and a directly matching subscription is revoked.
- File and team topics share a raw UUID namespace. Messages are classified by event payload before authorization (`library-change` as team; file events by their `file-id`/`fileId`) so an ID collision cannot inherit authorization from the other resource kind. Unclassified resource-channel messages are dropped.
- Only actively subscribed profile/system channels and classified resource channels can be relayed. Unknown non-profile/system channels are dropped. On disconnect, missed-pong threshold, ping error, or text-write error, the connection is closed to unblock `ReadMessage`; deferred session cleanup cancels the Redis loop, clears active subscriptions, and closes/unsubscribes Pub/Sub.
- Ping control frames use Gorilla's concurrent-safe control-write API. The WebSocket route remains legacy-compatible; this PR does not enable it for production editor traffic.

### Revision-history integrity

- Stale `update-file` requests require every unlabeled operation revision in `(baseRevn, currentRevn]` to exist in order and decode as a JSON change array with nonempty operation types. Labeled `file_change` snapshot rows are excluded because snapshots annotate a revision and are not operations in its change history.
- Missing revisions, null/empty/malformed data, and legacy Transit+zstd bytes return a typed `CompetingChangeHistoryError`; the endpoint responds `409 change-history-unavailable` before applying or committing the stale request.
- The existing best-effort `loadLaggedChanges` response path is not upgraded to a complete history-decoding contract by this change; malformed post-commit lagged payload behavior remains a separate follow-up. This is not evidence that legacy collaboration history is fully compatible.

## Disposable integration coverage added

`notifications_ws_integration_test.go` exercises the production `server.New` route and middleware with a real WebSocket client, PostgreSQL session/permission rows, and Redis Pub/Sub. It covers unauthenticated, missing-Origin, and cross-Origin upgrades; same-origin and explicit proxy-origin acceptance; permitted team/file subscriptions and delivery; delivery rejection after unsubscribe; cross-team rejection; permission revocation with dropped events and subscription cleanup; reconnect authorization; and cleanup after disconnect. `notifications_ws_lifecycle_test.go` uses a short deterministic ping interval with real WebSocket and Redis connections to prove missed-pong termination unblocks the read loop, closes Pub/Sub, and removes Redis subscriptions. Unit tests also cover stale queued messages and unknown channels. `files_update_integration_test.go` creates an actual revision, adds a labeled snapshot at the same `revn`, and verifies stale rebase succeeds with both operation rows and the snapshot present; the malformed legacy Transit+zstd case still asserts 409 without changing the file revision or adding a change row.
