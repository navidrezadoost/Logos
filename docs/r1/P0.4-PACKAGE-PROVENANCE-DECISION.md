## Requested written responses

For each external artifact, please provide a durable source-to-artifact statement with:

1. Canonical source repository, immutable commit, and commit-signature or owner-attestation evidence.
2. Package name/scope, version, publisher, build recipe/toolchain, and resulting artifact URL.
3. Independently trusted digest for exact archive bytes and registry/publisher signature verification result.
4. Exported API used by the historical consumer, compatibility evidence, and expected license/redistribution terms.
5. Explicit approval or rejection for a disposable candidate installation. A package scope, source, or version change remains unapproved unless written here by its owner.

For workspace-only edges, state the dependency class and how emitted declarations are resolved by both the historical frontend and any published MCP/plugin package. The six missing `plugins-runtime` dev-dependency resolutions remain a separate lock-generation concern; do not infer their versions from ranges.

## Scope boundary and requested decision

This branch records the CTO's existing no-scope-change decision and leaves all active dependency manifests and lockfiles untouched. A signed-off decision table cannot be completed by inferring an owner from npm maintainers or by treating a registry signature as source-commit provenance.

**Requested from CTO/Release Owner:** designate the responsible package/source owners and approve the information-request workflow. Until written package/source attestations and archive integrity evidence are supplied, keep the legacy installation/build paused. Option A remains an investigation path, not an approved dependency migration or runtime strategy.

The durable written request is open as [issue #62](https://github.com/navidrezadoost/Logos/issues/62). No owner has been inferred or assigned because the repository has no `CODEOWNERS` mapping.
