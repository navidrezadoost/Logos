# G0-B Authoritative Core, Domain Integrity and Platform Readiness Audit

**Status:** Evidence audit and proposal; no canonical document owner selected.
**Baseline:** `main` / `origin/main` at `41c88ca3217e9451883afeb50d93debbc3ded1ad` (PR #91, A8).
**DT-C3:** PR #90 head `bc3bf3b87dd141e0f670f726158b00cf43072d21`; its final Rust workspaces workflow and required checks passed, but the change is not in the recorded baseline. Track it as an **integration candidate**, not as accepted mainline capability.
**Scope:** Read-only source audit plus isolated core characterization tests. No production behavior, Go persistence, UI interaction, or schema was changed.

## Finding

The repository does not yet enforce one authoritative end-to-end document model. Rust `logos-types` is a candidate value-type source and generates a TypeScript subset, but the active React document store uses another shape/page model; Go persists legacy file-data JSON and change history; renderer/WASM consumes a derived projection; and offline persistence snapshots React state. Existing docs make this ownership gap explicit. A8 adds a strict renderer projection validator, but the A8 architecture note says the production Canvas is still on its legacy route; it is not document-wide validation or canonical persistence.

## Classification

- **IMPLEMENTED:** Rust value/geometry/token type crates; Rust token resolution; Rust Flex/Grid primitives; renderer WASM execution; Go transaction for `file_change`, file revision and data; Go stale-history gap checks; A8 renderer-only graph projection validation and recovery; React local snapshot and offline queue mechanisms.
- **PARTIAL:** Rust-generated TS compatibility; React ↔ renderer mapping; Go document update and snapshot/replay; layout authority; components; token persistence; XD conversion; generated type validation; native platform support.
- **MISSING:** An enforced canonical Document/Page/Shape graph contract shared by active React, Go and Rust boundaries; shared versioned conversion with unknown-field policy; typed document operations with preconditions/inverses; persisted prototype contract; cross-language graph validator; authoritative layout conformance suite.
- **UNVERIFIED:** Complete lossless schema round trips for real historical files; non-browser native rendering; Go snapshot consistency under races; collaboration/undo replay parity; true cross-engine layout equivalence; memory/performance baselines. Do not convert CI readiness or unit-test coverage into a performance claim.

## Recommended next narrow milestone

G1 should begin with **contract characterization and a pure Rust document-graph validator proposal**, not persistence writes: approve whether Rust owns canonical value/schema types, define compatibility envelope and unknown-field handling, define page-scoped tree and DeleteSubtree/Reparent/Reorder semantics, then validate golden legacy and React projection fixtures through explicit adapters. Acceptance should require duplicate/dangling/cycle/root/order and numeric validation fixtures, serialization round trips with extension retention/rejection, exact Flex/Grid fixture results, and no mutation on invalid operations. Chief Architect must decide the shared document contract before schema edits or Go persistence changes.
