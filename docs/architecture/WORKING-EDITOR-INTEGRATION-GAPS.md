## Direct answer: what does opening a project launch?

### Source-intended path

```text
React login / dashboard (logos-app/src/main.tsx → App.tsx)
  → DashboardPage resolves project → file → first page through Go RPC
  → api/client.ts::openWorkspace()
  → /workspace.html#/workspace?team-id=…&file-id=…&page-id=…
  → legacy Logos workspace shell generated by sync-logos-workspace.py
  → imports ./js/main.js, worker/main.js, JS libraries/config/translations and renderer assets
```

`main.tsx`, `LegacyHashRedirect.tsx`, `WorkspaceRedirect.tsx`, `DashboardPage.tsx`, and `api/client.ts` retain this compatibility path. `App.tsx` routes `/workspace/:projectId/:fileId` to a redirect; it does not mount `WorkspacePage`. The newer React editor in `pages/WorkspacePage.tsx` is source-present, but the current router has no route to it. Therefore the source intent is a React auth/dashboard plus separately generated legacy workspace; source does **not** establish what an already-deployed artifact launches.

### Build evidence from this worktree

1. `cd logos-app && npm ci --no-audit --no-fund` — passed without changing the lockfile.
2. `npm run build` — passed: SVG generation, TypeScript project build, and Vite production bundle. Output is `logos-app/build/` (React `index.html` and hashed assets).
3. `python3 scripts/sync-spa-to-dist.py` — copied the React SPA and emitted:

   ```text
   Missing workspace bundles in dist/js/. Ensure dist/js/main.js exists.
   Synced React SPA → …/logos-app/dist/ (index.html + assets/)
   WASM/static files under dist/js/ are unchanged.
   ```

   Its caller runs the workspace synchronizer with `check=False`; therefore the process can report successful SPA sync while the legacy workspace bundle is absent. The clean worktree had no generated legacy bundle producer artifact. `sync-logos-workspace.py` refuses to write `workspace.html` unless `dist/js/main.js` exists.

The build proves the React SPA compiles. It does not produce or verify the expected workspace JavaScript, worker, or complete editor artifact. This reproduces the source-level gap in `docs/r1/PKG-00-FRONTEND-ENTRYPOINT-ASSESSMENT.md` and is consistent with the preserved compatibility decision in `docs/r1/PKG-00-F03-LEGACY-WORKSPACE-COMPATIBILITY-DECISION.md`.

## Compatibility and ownership decision

Preserve `/workspace.html` and all current redirects while the product/release owner decides whether the historical legacy producer is to be recovered or the React `WorkspacePage` is to be migrated through an explicit controlled decision. The source-only P0 finding authorizes neither route retirement nor producer restoration. Do not fabricate `main.js`, silently point the dashboard at React `WorkspacePage`, or call the SPA artifact a complete editor.

## Blocking findings

1. **Editor artifact:** standard React build + sync does not produce required `dist/js/main.js`, so no supported full workspace artifact is demonstrated.
2. **Document hydration:** React `WorkspacePage` is not routed and reads local IndexedDB rather than the selected server file in its initialization effect.
3. **Durable save/reconnect:** React’s default sync adapters do not send to Go or fetch authoritative server state.
4. **Schema provenance:** Go’s only current migration cannot bootstrap a clean database; stale README `-migrate` advice is not an implemented migration runner.
5. **Contract/revision safety:** Rust, React, stored Malli/Transit shape formats and legacy change histories are not fully reconciled; undecodable competing changes are skipped/non-fatal in Go’s update path.
6. **Renderer:** one React canvas is passed to Skia/WebGL and WebGPU initialization; backend selection/ownership is unresolved.

Run the [P0 verification procedure](P0-VERIFICATION-PROCEDURE.md) only after an owner-approved, isolated database schema and complete supported editor artifact are available.
