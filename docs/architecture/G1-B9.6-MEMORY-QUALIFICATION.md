## Components

`test/benchmarks/g1-b9-6-memory-capture.mjs` captures Chromium V8 heap snapshots through CDP. It explicitly requests GC, validates complete snapshot structure and nonnegative V8 node self sizes, writes to a private temporary file, hashes the complete bytes, and publishes without overwriting an existing file. Comparisons require matching run, browser session, and fixture identity plus distinct checkpoints and artifact IDs. Equal content hashes are allowed for distinct captures. Deltas, including negative values, are observations only.

`test/benchmarks/g1-b9-6-memory-qualification.mjs` integrates that primitive with the existing production editor smoke page (`/g1-b9-5-editor-performance.html`). It requires the actual WASM renderer, runs the existing 21/85/341-shape fixtures and a deterministic seven-operation cycle, checks React/Rust semantic conformance and expected Canvas pixels, resets and verifies the fixture after each cycle, then captures a post-warmup baseline and post-cycle snapshots. It uses two fresh Chromium launches, at least five warmup cycles and at least two measured cycles for each fixture size. The default is five warmups and three measured cycles.

The harness does not assign a persistent identity to a test document. Its fixture builder owns a stable deterministic UUID, and `g1-b9-6-fixture-conformance.ts` attaches that identity only to the Rust candidate projection. Zustand `documentId` remains null throughout fixture hydration and resets. Missing or invalid fixture identity, Rust rejection, and React/Rust mismatch all fail closed. This preserves production identity eligibility rules.

The operations run in this order: sibling reorder, root reorder, create, child insertion, rename, reparent, and subtree deletion. Reordering precedes creation because the fixture's root-order contract starts with exactly two roots. Reparent precedes subtree deletion so deletion also checks the retained stable identity and membership of the moved leaf. Each operation records state hashes, selection, frame generation, Rust semantic-equivalence evidence, and framebuffer samples. Timing records are removed from the browser harness after each operation to prevent the test harness from accumulating them as apparent retained growth.

Raw heap snapshots are sensitive: they may contain document data. Output must be an owner-approved disposable fixture, outside the Git repository, in a directory restricted to the invoking user. The runner applies mode `0700` to the artifact root and mode `0600` to generated files. Do not upload or commit raw snapshots. Keep the run directory private and delete it according to the owner’s retention policy.

The runner refuses a dirty source tree, unmatched build commit/tree identity, a missing or altered served build asset, a browser bundle with a different embedded source identity, a non-loopback endpoint, repository-contained artifact output, absent/expired approval, missing Chromium, fewer than five warmups or two measured cycles, incorrect renderer/backend, missing WASM response, fixture mismatch, failed operation, semantic mismatch, pixel mismatch, missing GC/snapshot evidence, or missing artifact. Failure exits nonzero and reports `BLOCKED` or `FAILED`; it cannot emit a passing qualification status. Do not reduce warmups or cycles to make a failed run pass.

Before completion, the runner cross-checks every unique snapshot against its run, browser session, fixture, checkpoint and artifact reference; it re-reads every raw file and recomputes its byte count and SHA-256 before writing the report and again immediately before the final manifest. Any failure rewrites the outputs as `BLOCKED` or `FAILED`; a completed manifest is emitted only after the final integrity check. The private `memory-report.json` and `manifest.json` use mode `0600`. The manifest records source commit/tree identity, verified build artifact-set digest, report checksum, and relative raw artifact paths/checksums/byte lengths. The report records browser and OS metadata, renderer WASM hash and size, fixture identities and dimensions, explicit GC policy, operation/frame/pixel evidence, and raw snapshot metadata. The report status is `OBSERVED_NOT_QUALIFIED`, never PASS. A complete report is an observation set only; it does not satisfy G1-B10 authorization or a product memory threshold.

## Metric limits and interpretation

The measured delta is the sum of V8 heap snapshot node `self_size` values after explicit Chromium GC. It excludes Rust/WASM linear-memory capacity, GPU/WebGL resources, native browser allocations, other Chromium processes, and backend RSS. Renderer-reported WASM reserved capacity is recorded separately and must not be added to V8 self size or described as total memory. Snapshot parsing occurs in the Node runner, outside editor interaction timing.

The runner reports per-fixture minimum, maximum, mean, p50, and p95 of measured snapshot deltas without clipping negative values. These small sample distributions are not a leak verdict. There is no approved memory threshold, so even valid artifact collection cannot yield a performance pass.
