## G1-B9.6.1: isolated capture primitive

`test/benchmarks/g1-b9-6-memory-capture.mjs` implements a CDP `HeapProfiler` snapshot primitive, not a browser benchmark. The caller must independently establish that the environment is isolated and approved, the actual Rust/WASM production Canvas is loaded, a deterministic fixture is active, document operations succeed, and expected pixels are observed. An `authorizedIsolatedRun` argument is an additional fail-closed guard, **not proof** of owner approval.

Each capture requires a run ID, browser-session ID, fixture hash, checkpoint name, and destination. It enables `HeapProfiler`, explicitly invokes Chromium garbage collection, receives all snapshot chunks, writes a private temporary file, verifies the snapshot's structural fields and nonnegative V8 node self sizes, and publishes the final file without overwriting an existing artifact. It returns a SHA-256 digest, byte count, chunk count, node count, and total V8 snapshot self size. Failure to collect garbage, receive complete chunks, parse the snapshot, or publish the artifact is **BLOCKED**; partial files are deleted. There is no synthetic zero-byte success path.

`comparePostGcSnapshots` only compares captures with matching run, browser session, and fixture hash, explicit GC, and distinct checkpoints/artifacts. It returns an **observed snapshot self-size delta**, including negative values; it does **not** return a leak verdict, performance pass, or production memory claim.

The V8 heap snapshot excludes Rust/WASM linear-memory capacity, WebGL/GPU resources, native browser memory, and backend RSS. It is not a measure of total process memory. Parsing the raw snapshot in Node is outside browser interaction timing and must not be included in editor latency. Raw snapshots may contain document contents and must be collected only from an authorized disposable fixture, retained privately, and never committed to Git.
