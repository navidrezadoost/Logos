# P0.1 Track C — Document Compatibility Mapping and Fixtures

**Status:** Field-level gaps and boundary fixtures added; end-to-end conversions remain unverified
**Baseline:** `8f27fdfe4fe40a8787cff8d9a20cacde452088ec`
**Fixture set:** `test/fixtures/p0-document-compat/` (synthetic, no user data)

## Decision

Do not change the stored schema or introduce a replacement document type from this track. The fixtures expose the representations already in source and make two local boundary checks executable. There is no active, supported legacy-document → Go → React → Rust-renderer → save/reload adapter chain to test end-to-end. The remaining conversions/losses block a compatibility claim.

## Field-level mapping

| Field/feature | Historical Penpot/Go file-data shape | React editor projection | Rust domain/render input | Compatibility finding |
|---|---|---|---|---|
| Document/page identity and order | File `id`; ordered `pages`; `pages-index[pageId]`; each page has `objects` keyed by shape UUID. Go file row separately has `version`, `revn`, `vern`, features and data. | `DocumentState.pages`, `pageOrder`, `currentPageId`, `shapes`, and `Page.rootShapeIds`. | `logos-types::Shape` is a shape value, not a document/page container. Renderer receives shape records, not page/file identity. | No demonstrated Go `get-file` → React hydration adapter. React `WorkspacePage` currently restores local IndexedDB rather than selected server file. Root/page ownership must be explicit. |
| Shape ID and discriminator | UUID string; Transit enum values may arrive as keyword representations; Go repairs selected string enums to `~:…`. | `Shape.id: string`; `ShapeType` includes React-specific `ellipse`, `vector-network`, `component`, `instance`; renderer maps supported kinds to numeric discriminants. | `Shape.id: Uuid`; Rust `ShapeType` has frame/rect/circle/path/image/text/group/bool/component. | UUID-to-four-`u32` little-endian renderer write is explicit; type aliases and unsupported kinds need a versioned mapping, not `?? rect` fallback. |
| Geometry and transforms | Historical/Go objects carry `x`, `y`, `width`, `height`, `selrect`, `transform`, `transform-inverse`, and sometimes cached points. `selrect` also contains `x1/y1/x2/y2`. | `bounds: {x,y,w,h}`, transform tuple `[a,b,c,d,e,f]`, rotation. | Rust uses `selrect: Rect{x,y,width,height}`, `Matrix{a..f}`, rotation and optional cached points. WASM base ABI stores `selrect` as four f32 endpoints and transform as six f32. | Same intent, different field shapes/units and f64→f32 boundary. Fixture tests use non-zero origin and extent to catch xy/xyxy and w/h errors; no adapter test compares the full chain. |
| Parent/children/root | `parent-id`, `frame-id`, ordered `shapes`; nil UUID root frame is present in the page objects map. | Page root IDs are stored separately; shapes use nullable `parentId` and ordered `children`. | `parent_id`, `frame_id`, ordered `shapes`; Rust documents `None` for a root frame. | Nil-UUID root versus `null`/`None` and page root list require a normalization rule. Child ordering must round-trip. |
| Solid fill | Historical file map uses keys such as `fill-color` and `fill-opacity`; Go stores JSON/Transit-compatible map data. | `{type:"solid", color, opacity}`. | Serde fill is tagged with `fill-type:"solid"`, `fill-color`, `fill-opacity`. | Distinct tag/key schema. Historical/common serializer and current Rust agree on the *binary* 160-byte fill enum; that does not validate document JSON conversion. |
| Unknown extensions | Go filedata is a `map[string]any`; `NormalizeFileData`/`NormalizeShape` edit recognized fields while preserving other map entries. | Current `Shape` has no generic extension map. | Rust has `plugin_data: HashMap<String,String>`, which is narrower than arbitrary nested JSON. | `extension-p0` sentinel survives Go normalization/JSON round trip in the new Go fixture test; no React/Rust mapping preserves it today. This is a known loss probe, not a field to discard silently. |
| Text, effects and assets | Historical maps contain rich text trees, fills/strokes/effects and media IDs with backend storage references. | React projection contains some text/fill/stroke/effect/media fields but does not represent every legacy nested structure. | Rust types cover selected typography/fill/stroke/effects; render ABI uses separate text/font/image calls. | No rich-text run, font/variable-font, image ID, color profile, or effect conversion is covered by the fixture. Requires separate fixtures. |
| Components, variants, tokens, interactions | Historical library/component/variant/token/interaction data lives in document maps and related file/library records. | Component, token, and prototype state is split across stores; some stores are not included in IndexedDB snapshots. | Rust has component links and token registry/bindings, but not the same complete React instance/prototype contract. | No round-trip mapping, reference integrity, or reload proof. Must be handled before declaring a full document equivalent. |
| Revisions and unknown change formats | Legacy change history may be Transit+zstd; current Go writes JSON change rows. | React offline manager defaults to local state/no-op network adapters. | Rust rebase crate tests the algorithm but is not the current Go runtime’s linked implementation. | Go skips undecodable legacy competing rows and proceeds without rebase on a load error. Compatibility/fail-closed behavior remains open. |

## Reproduction

From repository root:

```bash
(cd backend-go && go test ./internal/filedata -run TestP0CompatibilityFixture -count=1)
cargo test --manifest-path rust/Cargo.toml -p logos-types --locked p0_compatibility_fixture
```

The focused Go fixture test and Rust shape serde test pass. The JSON fixture files parse. These tests run only their explicitly named single-language boundaries; they are not cross-process integration tests.

The hosted `Verify generated types are up-to-date` check for this PR fails before comparing generated files: the workflow invokes `make generate-rust-types CHECK=1`, which enables the `ts` feature, but `rust/logos-types/Cargo.toml` currently declares `ts = []` and leaves the `ts-rs` dependency commented out while Rust sources use `cfg_attr(feature = "ts", derive(ts_rs::TS))`. Reproducing `cargo check --manifest-path rust/Cargo.toml -p logos-types --features logos-types/ts --locked` from the clean `8f27fdfe` baseline fails with unresolved `ts_rs`; the failure is pre-existing, not caused by the fixture test. This track does not change the type generator or dependency contract. The dependent TypeScript check is skipped by CI after this failure.

## Required next compatibility gate

1. Reconcile this fixture against an authentic, legally retained historical document, preserving unknown fields and source provenance.
2. Implement or identify the existing Go→React projection; do not infer it from the React type declaration. Load a real file and compare IDs, root, geometry, hierarchy/order, fills, text, assets, components/tokens/interactions.
3. Feed the exact React projection through `scene.ts`; capture the actual 104-byte base record and 160-byte fill records and assert offsets/endianness against Rust, then render pixels through the supported editor route.
4. Save through the Go revision API, reload from PostgreSQL, and compare canonical document plus unknown extensions. Add stale revision/legacy Transit tests and require fail-closed recovery where history cannot be decoded.
5. Reopen and verify component/token/prototype state. No acknowledged server revision may depend solely on the local IndexedDB snapshot.

**Track C outcome:** fixture specifications and Go/Rust local tests are in place. The complete four-boundary compatibility and reload gate remains **OPEN**; no schema transformation or data-loss policy has been approved.
