# P0.1 Track A — Editor Runtime and Compatibility Decision

**Status:** Evidence review complete; no runtime option is approved for implementation
**Baseline:** `8f27fdfe4fe40a8787cff8d9a20cacde452088ec` (PR #52 merge)
**Historical producer snapshot:** `665bb1ef13c3eeff2e84bf6e0d588a6bdecc6a92` (parent of `ea3b966b`, which removed the active Clojure backend/frontend roots)
**Scope:** read-only source/dependency/API/ABI comparison plus a frozen-install feasibility check; no lock, route, renderer, or runtime changes.

## Decision in brief

**Do not switch the dashboard to React `WorkspacePage`, do not restore partial legacy assets, and do not retire `/workspace.html`. No complete editor runtime is verified on this baseline.**

The historical source is present in Git and offers the broadest Penpot-derived feature set, but its build is not reproducible as-is: a frozen install stops on frontend manifest/lock drift before producing any modules. The historical renderer build also silently exits success when its hard-coded `/opt/emsdk/emsdk_env.sh` is absent. React compiles but remains unrouted; its page does not hydrate from the selected server file, and its default offline sync is local/no-op. The Go RPC and WebSocket layers have substantial compatibility work but static route gaps and security/format caveats remain.

**Provisional direction:** Option C is the least-disruptive *strategy to investigate* after a supported legacy producer or another real editor runtime is proven. It is not yet an approved hybrid implementation because there is not currently a verified “working legacy editor” artifact to retain. Option A and B are not qualified by this evidence. Product/release owners must approve the next action after the blockers below are resolved.

## Historical producer evidence

At `665bb1e`, `frontend/`, `common/`, `backend/`, `render-wasm/`, `mcp/`, and `plugins/` co-exist. `frontend/scripts/build` runs the following sequence: pnpm dependency install; render-WASM build; MCP plugin setup/build; Shadow-CLJS main/worker release; JS library and asset packaging; then syncs `resources/public/` into `target/dist/`. `frontend/shadow-cljs.edn` declares `main`, `main-auth`, `main-dashboard`, `main-settings`, `main-viewer`, `main-workspace`, `shared`, `render`, `rasterizer`, `util-highlight`, and worker entrypoints.

### Reproducibility/supply checks

- Exact historical `pnpm install --frozen-lockfile --ignore-scripts` failed before code compilation; no package or lock was changed. Its failure names six missing devDependency specifiers plus a removed `@logos/plugin-types` workspace edge in `plugins/libs/plugins-runtime/package.json`.
- The frontend package pins pnpm `10.28.2`; the historical plugin and render-wasm workspaces declare other pnpm versions. Historical source declares Node `22.22.0`, Rust `1.91.0`, Emscripten `4.0.6`, Clojure language `1.12.2`, Shadow-CLJS `3.2.2`, and Clojure CLI/JDK versions in its development Dockerfile. The historical Clojure graph has no checked-in resolved dependency lock.
- Existing F06/F07 evidence records repeated `ECONNRESET` against exact commit tarballs `penpot/svgo@8c9b0e3…` and `penpot/draft-js@4a99b2a…`; those historical lock entries do not record archive integrity. F07 did not retry. No artifact mirror or checksum authority is approved.
- Historical `render-wasm/build` only builds when `/opt/emsdk/emsdk_env.sh` exists; otherwise it emits a warning and exits 0. In this host that file and `emcc` are absent. Current Rust CI pins Emscripten 4.0.6, but the historical shell does not pin an emsdk commit.
- The historical build injects a timestamp into `VERSION_TAG`; byte-for-byte reproducibility is not established even if a functional build is later recovered.

## HTTP/WebSocket/renderer compatibility findings

- **HTTP:** the Go server mounts `registerRPC` at `/api/main/methods/` with Transit middleware as well as the React `/api/rpc/command/` JSON mount. Static extraction found 24 direct RPC names in historical workspace data; 9 have no same-named Go route: `create-file-media-object-from-url`, `get-library-usage`, `ignore-file-library-sync-status`, `link-file-to-library`, `rename-file`, `set-file-shared`, `unlink-file-from-library`, `update-comment-thread-position`, and `update-file-library-sync-status`. A missing direct route may have an intended alternative contract, but no call-by-call mapping or runtime test was found. A separate whole-frontend scan found 26 historical RPC names without same-named Go routes (workspace calls overlap): `cancel-email-change`, `create-file-media-object-from-url`, `create-team-access-request`, `create-team-with-invitations`, `export`, `get-comment-thread`, `get-file-summary`, `get-library-file-references`, `get-library-usage`, `get-subscription-usage`, `get-team-invitation-token`, `get-team-users`, `has-file-libraries`, `ignore-file-library-sync-status`, `link-file-to-library`, `login-with-oidc`, `rename-file`, `request-email-change`, `set-file-shared`, `unlink-file-from-library`, `update-comment-thread-frame`, `update-comment-thread-position`, `update-file-library-sync-status`, `update-profile-notifications`, `update-profile-password`, and `update-team-photo`. Some may be superseded by different APIs; static name mismatch is a test queue, not proof every command is required in the workspace journey.
- **File changes:** legacy Clojure stores `file_change.changes` as Transit+zstd. Go stores JSON in the same conceptual column; `loadCompetingChangeSets` skips non-JSON rows, and the update path continues without rebase on a competing-change load error. Old client decoding/fast-forward of Go change payloads has not been proven end-to-end.
- **WebSocket:** historical client connects to `/ws/notifications?session-id=…`, sends Transit `subscribe-file`/`subscribe-team`, resubscribes on reconnect, and consumes presence/file/page/library events. Go implements the same URL/message names and Transit message encoding, so a protocol overlap is source-evidenced, not browser-verified. `websocket.Upgrader.CheckOrigin` currently returns `true`, and `subscribe-file` subscribes to an arbitrary ID without a file permission check. This is a security blocker for release until explicitly fixed and tested.
- **Renderer ABI:** historical Penpot `shapes.cljs` declares/writes 104-byte base-property records, matching the current Rust renderer ABI. Historical `common/.../types/fills/impl.cljc` computes `FILL-U8-SIZE = 4 + max(156,36,4) = 160` and writes color at record offset 4; current Rust `RawFillData` is 160 bytes aligned to 4, and PR #51 adds an ABI/pixel regression. This is a strong source-level compatibility seam for base-shape and fill data, **not** proof of every text/path/font/worker operation or complete editor startup.

## Security and maintenance

- `frontend/shadow-cljs.edn` binds nREPL to `0.0.0.0`; any isolated compile/run must bind development services to loopback or a network-isolated namespace.
- Exact historical dependency installs fail before compilation; direct GitHub tarballs are not integrity-pinned in the lock; F04 recorded Docker tool download resets. No dependency vulnerability audit was run on the recovered revision.
- The old workspace is a substantial ClojureScript/common codebase and its original support owner/window is not documented. Restoring it means maintaining its pinned toolchains, Clojure dependencies, MCP/plugin build, renderer, service/API contract, and release artifacts.
- The compatibility decision in `docs/r1/PKG-00-F03-LEGACY-WORKSPACE-COMPATIBILITY-DECISION.md` remains valid as a “do not silently retire” decision; it is not evidence that Option A has passed feasibility.

## ADR disposition / authorization

1. **Do not select A as supported today:** exact frozen install failure and missing renderer toolchain/outputs block the selection criteria.
2. **Do not select B because it compiles:** there is no routed React editor, accepted feature-gap closure, server document hydration, or durable sync proof.
3. **Use C as the provisional architecture direction only:** preserve the compatibility URL, establish an actual supported editor artifact, and migrate bounded features with explicit document/API/renderer boundaries. Since a working legacy artifact is not established, this is a planning recommendation—not authorization to wire a hybrid or change routes.

Reopen the runtime decision only after Tracks B/C deliver their contracts and a fully generated artifact passes the browser journey. No runtime/source change is included in this report.

**Browser evidence:** no legacy or React editor browser journey was run in Track A. The producer stops at frozen dependency resolution, and the current workspace consumer has no complete bundle. PR #51 / Run #236 remains standalone renderer evidence only.
